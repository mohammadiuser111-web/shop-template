# Shop Template - Project Prompt

## 1. معرفی پروژه

یک **قالب (Template) کامل و قابل فروش مجدد** برای سایت‌های فروشگاهی طراحی و پیاده‌سازی کن که شامل سه بخش اصلی است:

1. **فروشگاه (Store)** — نمایش و فروش محصول
2. **مجله/بلاگ (Magazine)** — تولید محتوا
3. **پنل ادمین (Admin Panel)** — مدیریت کامل سایت

### هدف نهایی

هدف نهایی این نیست که یک سایت اختصاصی بسازی؛ هدف ساخت یک **Boilerplate/Template حرفه‌ای** است که:

- برای هر کارفرمای جدید فقط با تغییر چند **متغیر پیکربندی** (رنگ، فونت، لوگو، نام برند، دیتابیس) آماده‌ی تحویل شود
- توسعه‌ی پروژه‌های بعدی را از هفته‌ها به روزها کاهش دهد
- ساختار کد آن‌قدر تمیز و مستند باشد که خودم (یا هر توسعه‌دهنده‌ی دیگری) بعد از مدت‌ها بتواند به‌راحتی در آن تغییر ایجاد کند

### الهام طراحی و تجربه‌کاربری

از سایت‌های زیر الهام گرفته شده است:
- دیجی‌کالا (digikala.com)
- ترب (torob.com)
- سایت خانومی
- باسلام

الهام‌گیری از نظر چیدمان، جریان خرید، فیلترها و پنل ادمین.

---

## 2. استک فنی (Tech Stack)

- **Backend:** Django + Django REST Framework
- **Frontend:** HTML5 + CSS3 (متغیرمحور با CSS Custom Properties) + JavaScript (Vanilla یا ماژولار — بدون فریمورک سنگین، سبک و سریع)
- **Database:** طراحی با لایه انتزاعی (Abstraction Layer) به‌گونه‌ای که جابه‌جایی بین PostgreSQL / MySQL / MongoDB با کمترین تغییر ممکن باشد. پیش‌فرض: **PostgreSQL** (به‌خاطر سازگاری کامل با Django ORM)
- **Cache/Queue:** Redis (برای کش، سشن، و صف کارهای پس‌زمینه با Celery)
- **Static/Media:** جدا از کد، با پشتیبانی از CDN
- **Deployment:** Docker + Docker Compose، آماده برای Nginx + Gunicorn، آماده برای CI/CD

### قانون طلایی جداسازی

- هر چیزی که «ثابت» است (گرید، ریسپانسیو، ریست CSS، ساختار کامپوننت‌ها، منطق جاوااسکریپت) در `static/` می‌ماند و دست‌نخورده باقی می‌ماند
- هر چیزی که «متغیر بین پروژه‌ها» است (رنگ، فونت، لوگو، نام سایت، متن‌های هدر/فوتر، شماره تماس) فقط در پوشه‌ی `theme/` تعریف می‌شود و از طریق CSS Variables و Context Processor به همه‌ی صفحات تزریق می‌شود

## 4. سیستم تم و شخصی‌سازی (Theming System) — بخش حیاتی

باید یک **Theme Engine ساده** طراحی شود:

1. فایل `theme/config.json` شامل:
   - نام برند، اسلوگان
   - لوگوی اصلی/موبایل/فوتر
   - پالت رنگی کامل (رنگ اصلی، ثانویه، پس‌زمینه، متن، هشدار، موفقیت، خطا — حداقل ۱۰ متغیر رنگی)
   - فونت فارسی و لاتین (نام + مسیر فایل)
   - اطلاعات تماس، شبکه‌های اجتماعی
   - متغیرهای مالی (واحد پول، نماد، پیش‌فرض مالیات)

2. این JSON در بک‌اند خوانده می‌شود و به‌صورت متغیرهای CSS (`--color-primary`, `--font-main`, ...) در `<head>` صفحات inject می‌شود (از طریق یک context processor یا template tag اختصاصی Django به اسم مثلاً `{% theme_vars %}`)

3. تغییر کامل ظاهر سایت (رنگ، فونت، لوگو) باید فقط با ویرایش یک فایل JSON ممکن باشد — بدون لمس هیچ فایل HTML/CSS/JS دیگر

4. یک پنل ساده در بخش تنظیمات ادمین هم اضافه کن که همین مقادیر را از طریق فرم قابل ویرایش کند (بدون نیاز به دسترسی به کد)

## 5. صفحات و قابلیت‌های فرانت‌اند (سمت کاربر)

طراحی باید **مدرن، تمیز، سریع، و کاملاً واکنش‌گرا (Responsive)** باشد. آیکون‌ها همگی از نوع **Outline و تک‌رنگ مشکی** باشند (ست یکپارچه، مثلاً از Feather Icons یا مشابه، سفارشی‌سازی‌شده)

### صفحات الزامی

- **صفحه اصلی**: اسلایدر/بنر اصلی، دسته‌بندی‌های ویژه، محصولات پرفروش، پیشنهاد شگفت‌انگیز، جدیدترین مقالات بلاگ، بنرهای تبلیغاتی
- **لیست محصولات** با فیلتر پیشرفته (دسته، برند، قیمت، ویژگی)، مرتب‌سازی، Pagination/Infinite Scroll
- **جزئیات محصول**: گالری تصویر با زوم، انتخاب Variant (رنگ/سایز)، موجودی لحظه‌ای، نظرات و امتیاز، محصولات مرتبط، افزودن به سبد با AJAX (بدون رفرش)
- **سبد خرید**: افزایش/کاهش تعداد، حذف، اعمال کد تخفیف، محاسبه هزینه ارسال، خلاصه سفارش زنده
- **تسویه‌حساب (Checkout)**: چند مرحله‌ای (آدرس → روش ارسال → روش پرداخت → تایید)
- **درگاه پرداخت**: لایه انتزاعی (Payment Gateway Interface) طوری که افزودن هر درگاه ایرانی (زرین‌پال، آیدی‌پی و ...) فقط با پیاده‌سازی یک کلاس جدید ممکن باشد
- **ورود / ثبت‌نام**: با شماره موبایل + OTP و ایمیل/رمز عبور، بازیابی رمز عبور
- **پروفایل کاربری**: سفارش‌ها، آدرس‌ها، علاقه‌مندی‌ها، اطلاعات حساب، تیکت پشتیبانی
- **بلاگ/مجله**: لیست مقالات، دسته‌بندی، تگ، جزئیات مقاله با نظرات، مقالات مرتبط، جستجو
- **جستجوی سراسری** با پیشنهاد لحظه‌ای (Autocomplete)
- **صفحات ثابت**: درباره ما، تماس با ما، قوانین، حریم خصوصی، FAQ
- **صفحات خطا**: 404، 500، 403 با طراحی اختصاصی

همه‌ی دکمه‌ها و فرم‌ها باید **کاملاً کارکردی** باشند (نه ظاهری/Mock) و با بک‌اند واقعی در ارتباط باشند.

## 6. پنل ادمین

پنل ادمین باید **مستقل، فارسی، راست‌به‌چپ، و به‌قدری ساده باشد که یک کاربر غیرفنی بتواند با آن کار کند.**

### ماژول‌های اصلی پنل

- **Dashboard**: آمار فروش، سفارش‌ها، درآمد، کاربران جدید، محصولات پرفروش، نمودار فروش/بازدید
- **مدیریت محصولات**: CRUD کامل + دسته‌بندی + برند + Variant + گالری + SEO + Import/Export اکسل/CSV
- **مدیریت سفارش‌ها**: تغییر وضعیت، فاکتور، اطلاعات پرداخت و ارسال
- **مدیریت مشتریان**: پروفایل، گروه‌بندی (VIP، جدید، وفادار)، مسدودسازی
- **مدیریت بلاگ**: افزودن/ویرایش مقاله، پیش‌نویس، زمان‌بندی انتشار، SEO
- **مدیریت نظرات**: تایید/رد نظرات محصول و بلاگ
- **کد تخفیف و کمپین**
- **مدیریت تبلیغات**
- **مدیریت رسانه (Media Library)**
- **مدیریت صفحات ثابت (CMS ساده)**
- **مدیریت ارسال و پرداخت**
- **مدیریت موجودی و انبار**
- **مدیریت کاربران ادمین و سطوح دسترسی (RBAC)**: نقش‌هایی مثل مدیر کل، اپراتور سفارش، نویسنده، پشتیبان — با پرمیشن مجزا برای هر بخش
- **پشتیبانی/تیکتینگ**
- **گزارش فعالیت‌ها (Activity Log)**: چه کسی چه تغییری داد، IP، زمان
- **تنظیمات کلی سایت**: شامل همان تنظیمات Theme (رنگ، فونت، لوگو) از طریق فرم ساده

### امکانات تکمیلی

- جستجوی سراسری
- Bulk Actions
- فیلترهای ذخیره‌شده
- حالت شب/روز

## 7. سیستم تبلیغات داخلی سایت

یک ماژول مستقل به اسم `ads` بساز که امکانات زیر را بدهد:

- ادمین بتواند بنر/تبلیغ برای **جایگاه‌های مشخص‌شده در سایت** (مثلاً: بالای صفحه اصلی، بین لیست محصولات، سایدبار بلاگ، پاپ‌آپ) تعریف کند
- برای هر تبلیغ: تصویر، لینک مقصد، عنوان، **تاریخ شروع و پایان نمایش**، وضعیت فعال/غیرفعال، اولویت نمایش
- شمارش تعداد نمایش (Impression) و کلیک (Click) برای هر تبلیغ، جهت گزارش‌گیری بعدی
- جایگاه‌های تبلیغاتی باید در تمپلیت‌ها به‌صورت Tag/Component آماده باشند (`{% ad_slot "homepage_top" %}`) تا افزودن جایگاه جدید ساده باشد

## 8. کارایی و مقیاس‌پذیری (الزامی)

سایت باید بتواند **بار همزمان ۱۰۰۰ کاربر** را بدون افت محسوس هندل کند:

- استفاده از **Redis** برای کش صفحات پرترافیک (صفحه اصلی، لیست محصولات) و کش Session
- **Query Optimization**: استفاده صحیح از `select_related` / `prefetch_related`، ایندکس‌گذاری روی فیلدهای پرجستجو
- **Pagination** درست در تمام لیست‌ها (جلوگیری از Load کامل دیتابیس)
- فایل‌های استاتیک و مدیا از طریق **Nginx** یا CDN سرو شوند، نه از طریق Django
- **Lazy Loading** تصاویر، فشرده‌سازی تصاویر (WebP)
- **Gunicorn با Worker متعدد** + امکان افزایش افقی (Horizontal Scaling) با Docker
- **Celery + Redis** برای کارهای سنگین/غیرهمزمان (ارسال ایمیل، پردازش سفارش، گزارش‌گیری)
- Minify کردن CSS/JS برای نسخه Production

## 9. تست (الزامی و کامل)

باید **تست بک‌اند و تست فرانت‌اند** به‌صورت کامل نوشته و اجرا شود:

### تست بک‌اند

- تست واحد برای مدل‌ها، سریالایزرها، ویوها در تمام اپ‌ها
- تست یکپارچگی برای جریان‌های کلیدی: ثبت‌نام → ورود → افزودن به سبد → تسویه‌حساب → پرداخت → مشاهده سفارش
- تست پرمیشن‌های پنل ادمین (هر نقش فقط به بخش مجاز خودش دسترسی داشته باشد)
- تست بار (Load Test) ساده با ابزاری مثل Locust برای بررسی رفتار زیر بار ۱۰۰۰ کاربر همزمان

### تست فرانت‌اند

- بررسی تمام صفحات از نظر: چیدمان (Layout)، واکنش‌گرایی در سایز‌های مختلف (موبایل/تبلت/دسکتاپ)، کارکرد صحیح تمام دکمه‌ها و فرم‌ها
- تست سناریوهای کاربری با Playwright یا Selenium:
  - جستجو و فیلتر محصول
  - افزودن/حذف از سبد خرید
  - فرآیند کامل خرید تا پرداخت
  - ورود/ثبت‌نام/فراموشی رمز
  - ارسال نظر و مشاهده در صفحه
  - کار با تمام بخش‌های پنل ادمین (افزودن محصول، تغییر وضعیت سفارش، افزودن مقاله، افزودن تبلیغ)

- بعد از هر تست، در صورت پیدا شدن باگ یا ناهماهنگی، اصلاح شود و دوباره تست شود تا تمام موارد سبز (Pass) شوند

نتیجه‌ی تست‌ها باید در گزارشی کوتاه در `docs/TEST_REPORT.md` ثبت شود
